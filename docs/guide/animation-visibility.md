检视、攻击或奔跑时闪一下，可能是轨道插值、动作交接、父子缩放、显隐配置或材质问题。先确定消失的是整把武器、某个道具，还是只有手臂，再记录动画名称与时间点；不要直接将所有可见性保护关闭。

## 先区分原因

| 表现 | 核对方法 | 对应处理 |
|---|---|---|
| 只在两个关键帧之间突然变大 | 检查父子骨骼的局部与全局缩放，采样中间帧 | 修正源绑定或烘焙方式，重新导出 |
| 正常大小的网格移动到某处就缺面 | 检查实际蒙皮后的模型空间坐标与 `hide_position_distance` | 按这把武器的动作范围校准距离 |
| 位置提早跳到下一帧 | 检查同一节点 T/R/S 的输入时间表，以及游戏加载器实际采样 | 在导出副本中对齐时间表 |
| 动作结束突然回到另一种姿态 | 检查尾帧、idle 基准、增量编码与动画层交接 | 修正动作边界或层配置 |
| 只在特定光影下消失 | 对比透明、深度、材质和渲染路径 | 按材质或渲染问题排查，不能只改动画距离 |

## 模型空间隐藏范围

`animation_visibility` 放在武器的 **render JSON**，不属于 Lua `config` 接管的七组动画配置。以下片段只演示调整距离，合并时保留原有显隐规则：

```jsonc
"animation_visibility": {
  "hide_position_distance": 32
}
```

| 字段 | 加载器缺省值 | 含义 |
|---|---:|---|
| `enabled` | `true` | 相关动画可见性规则开关 |
| `hide_position_distance` | `16` | CPU 三角形过滤：任一顶点蒙皮后模型空间坐标的绝对值在任一轴上超过此值时过滤该三角形；不是距玩家的米数，也不是球形半径 |
| `max_triangle_edge` | `2.5` | 异常拉伸判定的最小边长门槛 |
| `max_edge_stretch` | `8` | 同时与原边长的拉伸倍数比较；不是模型整体尺寸 |
| `hide_bone_move_distance` | `12` | 配合骨骼隐藏规则使用，不等同于顶点距离过滤 |
| `first_person_only_bones` | `[]` | 只在第一人称显示的骨骼，例如检视道具 |

`hide_position_distance: 0` 只关闭这一项距离过滤，不能视为推荐修复。异常边长保护有独立条件；也不要用 `enabled: false` 掩盖源动画错误。这些 CPU 检查不等于所有 GPU 或光影路径都执行相同过滤。

## 怎样确定数值

1. 使用实际发布 JAR 加载最终 GLB，检查全套动作，包括检视道具、奔跑、攻击和随机掏刀变体。
2. 检查关键帧之间、动作开始/结束以及与 idle 混合时的姿态。`idle_active` 若按增量编码，必须在正确基准上解码。
3. 统计蒙皮后的最大绝对坐标 `M = max(abs(x), abs(y), abs(z))`。分骨骼包围盒可以提供保守上界，但最终要验证原先缺面的时点。
4. 根据实际范围留余量，而不是为所有模型复制一个固定数字。重新更换 GLB 后再次校准。

2026-11-14 的三角洲近战包修复采用 `ceil((M × 1.25 + 4) / 4) × 4` 作为本次调校规则，**不是加载器默认公式**。电锯惊魂为 48、暗星两形态为 40、重塑为 36、赤枭为 28，其余本轮处理条目为 32。挽歌已有独立修复；黑伤刀光有专项配置，不能套用普通刀具范围。

## 父子缩放与 TRS 时间表

父骨缩至 `0.0001`，子骨再用 `10000` 反向抵消，即使在关键帧上看似正常，分别插值时仍可能造成巨大几何。尤其要检查导入器的 Segment Scale Compensate、Blender 的缩放继承和约束烘焙。只有确认父骨用于控制整个道具显隐后，才能据源动画重建相应子轨道；不能统一把所有子骨缩放改成 1。

当前导出流程应对每个节点的位置、旋转、缩放使用输入时间的并集：T/S 线性采样，四元数 R 使用 SLERP；需要保留源曲线形状时先适当加密。处理导出副本，保留源工程曲线。还要用实际游戏加载器对照中间帧，Blender 回导正确不能证明该加载器采样也正确。

## 验收边界

本次配置回归覆盖 18 个武器条目、272 段动作和 1,088 个原始峰值/半权重混合姿态，原先 119 段阳性误隐藏样本已消除。这是实际加载器与 CPU 几何检查结果，不等于 GPU、光影、手部接触或声音均已验收。

发布前完整重启游戏，分别检查开/关光影、第一人称、第三人称及展示场景；记录仍异常的动作与时点。更多检查见[动画制作](animation.md)和[调试与发布](debugging-release.md)。
