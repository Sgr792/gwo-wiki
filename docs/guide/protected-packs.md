当前可编辑保护包格式为 **v2**，需搭配支持该格式的 GWO 构建。旧 v1 包仍能读取，但仍按原来的严格完整性规则处理；只换新 JAR 不会把旧包自动变成可编辑包，需由发布者重新打包。

多个历史构建使用过相同的 `1.1.1-beta` 版本号。判断兼容性应核对发布者提供的具体 JAR/包及文件校验信息，不能只看版本文字。

## 安装 ZIP 或完整解压目录

内容包放在当前游戏目录的 `gwo/` 下，JAR 放在 `mods/` 下。可以保留原 ZIP，也可以完整解压成同名文件夹；两种形式只保留一种。

解压后保持 `pack.mcmeta`、`META-INF` 及所有内容文件的原相对路径，不能只复制 `assets/`，也不能多套一层目录。不要改动受保护媒体、签名头或索引，不要混入编辑器的临时文件、备份文件或符号链接。新增、删除、改名文件需要发布者重新打包。

## 直接修改原路径中的配置

v2 将以下已有文本条目标记为可编辑：

- `pack.mcmeta`。
- `.lua` 脚本。
- `assets/` 外的 `.json`，包括武器、render、配件、弹药及 `data/` 配置。
- `assets/<namespace>/sounds.json`。

可以在 ZIP 内原路径编辑，或编辑完整解压目录中的对应文件，**不需要新增 `config/gwo/overrides/`**。编辑前退出游戏并备份原包，保存后完整重启。JSON 必须有效，不能有重复键；Lua 和内容定义仍需通过各自校验。媒体仍受保护，修改配置不等于可以替换加密模型或音频。

例如只改第一人称模型 FOV，在现有 `camera` 对象中修改这个数值，保留其他字段：

```jsonc
"camera": {
  "model_fov": 70
}
```

`camera.model_fov` 有效范围为 1～179。它不等于 Minecraft 世界 FOV，也不是瞄准倍率。

## 单人游戏与联机规则

单人游戏也有内置服务端。有效的 v2 配置修改可以被本地客户端和内置服务端共同读取，媒体完整性验证仍然执行。错误不会因为“不是服务器”而失效。

联机时比较规范化后的 JSON 和 Lua。空白、JSON 对象键顺序及等价数值写法不影响比较；玩法数值、未知字段和 Lua 仍参与校验。当前仅允许 `weapons/` 或 `attachments/` 下 JSON 的这些有效叶子字段因玩家显示偏好而不同：

| 路径 | 可不同的字段 |
|---|---|
| `camera` | `model_fov` |
| `first_person`、`ground`、`fixed`、`modify_screen`、`sprinting`、`offhand_stowed` | 各对象直接包含的 `translation`、`rotation`、`scale` |
| `third_person_pose.gun.lowered`、`third_person_pose.gun.raised` | `translation`、`rotation`、`scale` |

不是整份 render JSON 都免校验。后坐力、倍率、伤害、容量、射速、动画时序和 `animation_visibility` 等设置仍需与服务器一致。当前相关构建使用协议 **23**，客户端和服务端应使用匹配版本。

## 提示验证失败时

先区分本地配置失败、服务端配置失败、玩法不一致和受保护资源损坏。保存完整日志及“GWO 资源状态”中的诊断文字，再按顺序检查：

1. 是否同时安装了 ZIP 与文件夹，或重复内容包。
2. 使用的是可编辑 v2 包还是严格 v1 包，JAR 是否匹配。
3. JSON/Lua 是否有效，有没有编辑器备份、缺失文件或错误目录层级。
4. 是否改动了仍需双端一致的参数，或修改了受保护媒体。

恢复发布者提供的完整原包可用于对照；不要删除签名文件或关闭验证来绕过错误。关于普通内容包发布与资源重载，见[调试与发布](debugging-release.md)。保护格式减少直接提取，不提供联网授权，也不保证对修改客户端不可破解。
