# Blockbench：Bedrock 实体模型与动画

[返回制作方式选择](./choose-workflow.md)

需要手臂起始工程时，可下载[Blockbench 手臂源模板](./arm-templates.md)。

这条路线在 Blockbench 中完成方块模型、分组层级、UV 和动画，不需要先学习 Blender。

::: warning 使用前确认
需要包含本次格式更新的开发版；游戏验收仍待完成。选择 Bedrock 实体模型格式，不是 Java 方块/物品模型，也不是仅保存 `.bbmodel` 就能放进游戏。当前支持数值关键帧，不支持 Molang、实体动画控制器和 `poly_mesh`。
:::

## 1. 创建工程

在 Blockbench 中创建 Bedrock 实体项目。设置清楚的模型标识与纹理尺寸，保存可编辑的 `.bbmodel` 工程。

一个导出的几何文件只放一个 `minecraft:geometry`。不要把多个实体定义放进同一文件。

**完成标准：**工程类型是 Bedrock 实体，而不是其他导出格式。

## 2. 方块建模

先使用少量方块搭出枪身与弹匣。统一方向，使最终模型符合 GWO 枪口 `+X` 的参考方向。

Bedrock 位置按 16 模型单位对应 1 渲染单位换算。不要给位移曲线再额外乘一次相同缩放。

**完成标准：**方块位置、尺寸和整体朝向正确。

## 3. 分组、枢轴与挂点

在大纲中建立分组；导出后分组对应骨骼节点。一个机构的方块放进同一组，把组的枢轴放在其转轴或运动参考点。

正式第一人称武器沿用 `root → tag_view → tag_ads → tag_weapon`；`tag_camera` 与 `tag_ads` 同级。完整职责见[模型规范](./models.md)，其中的节点名同样适用，不需要创建 Blender Armature。

挂点可以使用有明确名字的分组或受支持的 locator。不要把只需随枪运动的挂点放到相机分支。

**完成标准：**旋转一个组时，只有该分支中的方块跟随，其他机构不被带走。

## 4. UV 与贴图

在 Blockbench 中分配方块 UV，制作或导入 PNG 基础色。盒式 UV 和每面 UV 均可使用；每面 UV 中未指定的面不会绘制。

先用有明显正反方向的测试纹理检查映射。其他贴图仍通过[共用材质配置](./firearms.md)绑定；不使用每面的 `material_instance` 切换材质。

**完成标准：**各面的纹理方向与预期一致，没有意外漏面。

## 5. 数值动画

进入动画工作区，新建并命名动作，给分组设置位置、旋转或缩放关键帧。

先完成待机与一个简单动作，再逐步加入掏枪、开火、换弹。每个动作明确长度及是否循环：

- 位移与旋转相对初始姿态制作。
- 使用数值常量或数值关键帧，不填写 Molang 表达式。
- 支持 linear、Catmull-Rom 和 pre/post 数值。
- 事件帧、换弹提交与声音仍由 GWO 配置，不靠 Bedrock 实体声音/粒子事件触发。

**完成标准：**每个动作能独立播放，零时长静态姿态、循环动作和一次性动作区分清楚。

## 6. 导出与检查

分别导出：

```text
example.geo.json
example.animation.json
example.png
```

`.bbmodel` 是编辑工程，不是游戏加载文件。模型与动画的分组名必须对应；保留动画 JSON 中的完整动作名。

重新打开导出的几何与动画，确认层级、枢轴、贴图与动作；检查 JSON 的位置、旋转、缩放值是否都是数值。

**完成标准：**导出的文件能恢复正确模型和动作。然后阅读[快速开始](./getting-started.md)、[格式配置示例](./bedrock-empty.md)，进入[共用配置教程](./first-firearm.md)。

共用教程中的 GLB 文件名只是示例。使用本路线时替换为自己的 `.geo.json` 和 `.animation.json` 路径，无需转换成 GLB。
